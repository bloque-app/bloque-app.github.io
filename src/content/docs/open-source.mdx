them, run them and check them. This page covers what is common to every project. Each repository's
own files are authoritative for that project.

## Reporting a security issue

**Do not open a public issue, discussion or pull request for a security problem.**

Use GitHub's private vulnerability reporting, in the affected project's repository: on its
_Security_ tab, choose _Report a vulnerability_. That opens an advisory that only you and the
maintainers can see. A project's `SECURITY.md`, where it has one, gives its response times and scope;
aledgent's is in [its repository](https://github.com/bloque-app/aledgent/blob/main/SECURITY.md). If
you're not sure which project is affected, report it in the one closest to the problem; the
maintainers will move it.

Please do not test against Bloque's live services. Every project can be run locally for that.

## Contributing

Contributions are welcome, through pull requests on each project's repository. Read the project's
`CONTRIBUTING` first: it says how a change is proposed, reviewed and tested there.

- [aledgent: CONTRIBUTING.md](https://github.com/bloque-app/aledgent/blob/main/CONTRIBUTING.md)

Every commit carries a `Signed-off-by:` line with your real name and email. It certifies the
[Developer Certificate of Origin 1.1](https://developercertificate.org/): that you wrote the change,
or have the right to submit it under the project's licence. `git commit -s` adds it. Contributions
are accepted under the licence of the files they change. There is no separate contributor licence
agreement.

## Names and marks

The code is open; the names and marks are not. "Bloque", "aledgent", "bezent", "rutent", "evmhot",
their symbols and lockups, and the "by bloque" signature belong to Pagos Cube LLC (Bloque), and no
open-source licence of any project grants rights to them.

You may use the names to refer to the projects truthfully, for example to say that your software
works with aledgent, or that it is a fork of it. A fork or a product built on the code needs a name
and a mark of its own, and must not suggest that Bloque made, endorses or supports it. The
[Brand](../brand/) page has the files and the rules for using the marks when you write about the
projects.
